# Choosing the page system

Use when creating a deck without an exact template. A page system is a consistent reading order and visual hierarchy, not merely a color preset. For a supplied style reference, let the reference contract lead.

## Pick the explanation the audience needs

| Communication job | Suitable visual structure | What makes it substantive |
| --- | --- | --- |
| Explain a construction plan | System overview, responsibility map, process and correction paths | Inputs, controls and deliverables connect visibly |
| Present research | Question, method, figure/table, interpretation and limitation | Evidence supports the conclusion; generated art never replaces real results |
| Seek a management decision | Recommendation, comparable options, evidence and trade-offs | The audience can see what decision follows and why |
| Demonstrate a product | Real user situation, product state, annotated workflow, outcome | Screenshots illustrate the described action rather than decorate the page |
| Explain implementation | Architecture, interfaces, state changes, failure/recovery path | Arrows have consistent semantics and identify dependencies |
| Tell a brand or concept story | Image-led compositions with a clear sequence of ideas | Imagery carries a specific idea; the text does not repeat it |

Choose a dominant system for the deck, then vary layouts according to the evidence. Keep typography, colors, reading direction and recurring elements consistent. Do not force every subject into a cover, three cards, a timeline and a summary. Repeated layouts can be useful for synchronized comparisons; unrelated pages should not look identical merely because one layout was easy to code.

## Plan the visual before writing the slide module

In the slide plan, record:

- The main explanation and the evidence that supports it.
- The content object: native chart/table, editable diagram, screenshot, photo or schematic illustration.
- The reading path and visual emphasis.
- Required labels, actor relationships and source notes.
- How it differs meaningfully from adjacent slides while retaining the deck's identity.

For requested alternative versions, compare them without color: do their reading order, visual weight, relationship structure or evidence strategy differ? If only the accent changed, there is still one design.

## Density and hierarchy

A professional deck can be dense or sparse. Use the audience, reference and viewing conditions to choose density. Allocate space to the main explanation first, and ensure text remains readable at the intended display size.

When text does not fit, decide whether to shorten the wording, rearrange the explanation or place supporting detail in notes. Preserve required evidence. Do not silently shrink everything or remove the mechanism in pursuit of whitespace. Conversely, adding illustrative objects does not fix a slide whose central claim is unclear.

For large decks, establish shared dimensions, fonts, color roles and asset conventions before dividing page work. Use independent page modules only when they reduce complexity; a four-page revision normally needs one small builder, not a production framework.
